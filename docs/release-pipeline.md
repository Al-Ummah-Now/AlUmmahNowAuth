## Workers and environments

| Worker | QA | stage | prod |
|---|---|---|---|
| auth (issuer) | `al-ummah-now-auth-qa` · auth.qa.alummahnow.net | `al-ummah-now-auth-stage` · auth.stage.alummahnow.net | `al-ummah-now-auth` · auth.alummahnow.net |
| profile | profile.auth.qa.alummahnow.net | profile.auth.stage.alummahnow.net | profile.auth.alummahnow.net |
| admin | admin.auth.qa.alummahnow.net | admin.auth.stage.alummahnow.net | admin.auth.alummahnow.net |
| audit-consumer | `audit-events-qa` | `audit-events-stage` | `audit-events` |

Stage config is `env.stage` in each app's wrangler file, next to `env.production`. The config check (`scripts/check-wrangler-config.ts`) enforces that both envs have the same binding names and kinds. Only resource ids, routes and env-specific vars may differ.

## Issuer and clients on stage

Tokens carry `iss`, so stage has its own issuer, `https://auth.stage.alummahnow.net`. It also has its own D1 (`al-ummah-now-d1-stage`), KV and signing keys. A stage token is never valid in prod.

Stage registers a mirror of every prod client with stage redirect URIs: profile, auth admin (M2M), the web client for `videos.stage.alummahnow.net`, and the admin-web client. Seeding is in `apps/auth/scripts/seed-stage.ts`.

## D1 migrations

- `migrations/` is the prod history. Stage applies the same directory, so every migration runs on stage before prod.
- `migrations-qa/` is QA's diverged history. New migrations go into both.
- Migrations are append-only and expand-only (SPEC §6.1). CI checks the first rule. Reviewers check the second.
- `apps/auth/migrations/schema.snapshot.sql` is generated by applying `openauth migrate` and all app migrations to an empty local D1. CI fails if it is stale. Regenerate it with `pnpm --filter auth schema:snapshot`.
- An `@al-ummah-now/openauth` version bump can change openauth's own tables. Regenerate the snapshot in the same PR.

## Email codes in E2E

See SPEC §9.2. Summary for this repo:
- Addresses `@e2e.alummahnow.net` on QA/stage go to the KV sink `test:email:<addr>` (10 min TTL), not to Resend. Auth still resolves `RESEND_API_KEY` first, so a missing secret fails the same way it would in prod.
- Tests read codes with `GET /test/email/<addr>` + `X-E2E-Secret`. Every `/test/*` route needs that header and returns 404 otherwise.
- The sink is off unless `ENVIRONMENT ∈ {development, qa, stage}`, the `E2E_CODE_SINK_SECRET` binding exists, and the issuer is not `auth.alummahnow.net`. Prod config can't bind the secret: the config check fails.

## Release and rollback

- PRs: `test.yml` (type-check, unit, config + migration checks) and `qa-e2e.yml` (deploy to QA, E2E, including `e2e/tests/release/`).
- Merge to `main`: `release.yml` builds once, deploys stage, runs smoke and E2E on stage, then promotes each prod worker through Workers versions (upload → `@0%` + version-override smoke → `@100%` → smoke). If prod smoke fails, it rolls back automatically.
- Rollback: Actions → **Rollback** → Run workflow, or `pnpm release:rollback` locally.

| Incident | Test |
|---|---|

| Forgot-password crash on unknown email (#179) | `e2e/tests/release/forgot-password.spec.ts`, `send-code-handler.test.ts` |
| Prod sign-in failed after registration (web redirect_uri) | `e2e/tests/release/signup-signin.spec.ts` for the profile and admin clients; the web client is covered in AlUmmahNow |
